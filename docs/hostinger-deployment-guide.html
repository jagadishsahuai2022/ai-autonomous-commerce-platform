Step 2. Initial Server Setup & Security

Harden the server before deploying anything

SSH into your server

From your local Windows terminal (PowerShell or Windows Terminal):

ssh root@YOUR_SERVER_IP

Or use Hostinger's Browser Terminal from hPanel → VPS → Terminal (no SSH client needed).

Update system packages

apt update && apt upgrade -y

Create a deploy user (don't run Docker as root)

# Create user with sudo privileges adduser deploy usermod -aG sudo deploy # Set up SSH key for the deploy user mkdir -p /home/deploy/.ssh cp ~/.ssh/authorized_keys /home/deploy/.ssh/ chown -R deploy:deploy /home/deploy/.ssh chmod 700 /home/deploy/.ssh chmod 600 /home/deploy/.ssh/authorized_keys

Configure firewall (UFW)

# Allow SSH, HTTP, HTTPS only ufw allow OpenSSH ufw allow 80/tcp ufw allow 443/tcp ufw enable # Verify rules ufw status verbose
🔒 Security: Do NOT open ports 5432, 6379, 9093, 29092, 3001, 3002, 3010, 8001-8004 to the internet. They stay internal to Docker. Only 80 (HTTP) and 443 (HTTPS) are exposed via Nginx reverse proxy.

Install fail2ban (brute-force protection)

apt install fail2ban -y systemctl enable fail2ban systemctl start fail2ban

Disable root SSH login (optional but recommended)

# Edit SSH config nano /etc/ssh/sshd_config # Change these lines: PermitRootLogin no PasswordAuthentication no # Restart SSH systemctl restart sshd

After this, SSH in as: ssh deploy@YOUR_SERVER_IP

⏱ ~8 minutes

Step 3. Install Docker & Docker Compose

Hostinger may offer Docker as a 1-click template, but manual install gives latest version

💡 Hostinger Docker Template: If you selected "Docker on Ubuntu" during VPS setup, Docker is already installed. Skip to the verification step. Otherwise, follow below.

Install Docker Engine (official method)

# Add Docker's official GPG key & repo sudo apt install ca-certificates curl gnupg -y sudo install -m 0755 -d /etc/apt/keyrings curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg sudo chmod a+r /etc/apt/keyrings/docker.gpg echo \ "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \ $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \ sudo tee /etc/apt/sources.list.d/docker.list > /dev/null # Install Docker + Compose plugin sudo apt update sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y

Add deploy user to docker group

sudo usermod -aG docker deploy # Log out and back in for group change to take effect exit ssh deploy@YOUR_SERVER_IP

Verify installation

docker --version # Should show Docker 27.x+ docker compose version # Should show v2.x+ docker run hello-world # Should print "Hello from Docker!"
⏱ ~5 minutes

Step 4. Configure Swap Space

KVM 2 Critical — prevents OOM during Docker builds. KVM 4 Recommended as safety net.

Create and enable 4 GB swap file

# Create 4 GB swap (2 GB for KVM 4 is enough) sudo fallocate -l 4G /swapfile sudo chmod 600 /swapfile sudo mkswap /swapfile sudo swapon /swapfile # Make permanent (survives reboot) echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab # Optimize swap behavior echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf echo 'vm.vfs_cache_pressure=50' | sudo tee -a /etc/sysctl.conf sudo sysctl -p

Verify swap

free -h # Should show: # total used free shared buff/cache available # Mem: 8.0Gi ... ... ... ... ... # Swap: 4.0Gi 0B 4.0Gi
⚠ Why swap matters for KVM 2: Your 10 containers use ~2 GB at runtime, but Next.js build peaks at 3–4 GB additional. Without swap, the Linux OOM killer will terminate processes mid-build. With 4 GB swap on KVM 2, effective memory = 12 GB (8 GB RAM + 4 GB swap). Builds will be slower but won't crash.

Step 6. Production Docker Compose Configuration

Modify the compose file for production use on Hostinger

Create a production override file

Instead of editing the main compose file, create an override that changes ports for production (all traffic goes through Nginx):

nano docker-compose.prod.yml
docker-compose.prod.yml # Production overrides for Hostinger VPS deployment # Usage: docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml up -d services: # Remove external port mappings — only Nginx talks to services postgres: ports: !override [] # Keep internal Docker networking only redis: ports: !override [] zookeeper: ports: !override [] kafka: ports: !override [] environment: KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:29092 # Remove PLAINTEXT_HOST since no external access needed api: ports: !override - "127.0.0.1:3001:3001" # localhost only — Nginx proxies restart: unless-stopped web: ports: !override - "127.0.0.1:3000:3000" # localhost only — Nginx proxies environment: NEXT_PUBLIC_API_URL: https://yourdomain.com/api NEXT_PUBLIC_AI_SERVICE_URL: https://yourdomain.com/ai NEXTAUTH_URL: https://yourdomain.com restart: unless-stopped ai-service: ports: !override - "127.0.0.1:8001:8000" restart: unless-stopped intent-parser: ports: !override [] restart: unless-stopped product-aggregator: ports: !override [] restart: unless-stopped product-ranking-engine: ports: !override [] restart: unless-stopped

KVM 2 Only — Add resource limits to prevent OOM

On KVM 2 (8 GB), set memory limits so no single container can consume all RAM:

Add to docker-compose.prod.yml (KVM 2 only) services: kafka: deploy: resources: limits: memory: 1024M reservations: memory: 512M zookeeper: deploy: resources: limits: memory: 384M web: deploy: resources: limits: memory: 1536M # Next.js needs headroom for builds api: deploy: resources: limits: memory: 512M
💡 KVM 4 users: You don't need resource limits with 16 GB RAM. Skip this sub-step.

Step 7. Build & Launch All Services

The moment of truth — building and starting the full stack

KVM 2 — Build services sequentially (prevents OOM)

With only 2 vCPU and 8 GB RAM, build one heavy service at a time:

cd /home/deploy/delegatecart # Build infrastructure services first (lightweight) docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d postgres redis zookeeper kafka # Wait for them to be healthy sleep 30 # Build API (Node.js — moderate memory) docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ build api docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d api # Build Python services (lightweight, can do together) docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ build ai-service intent-parser product-aggregator product-ranking-engine docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d ai-service intent-parser product-aggregator product-ranking-engine # Build Web LAST (Next.js build is the heaviest — 3-4 GB peak) docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ build web docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d web
⏱ ~20 minutes total on KVM 2

KVM 4 — Build everything at once

With 4 vCPU and 16 GB RAM, you can build and start everything in one command:

cd /home/deploy/delegatecart # Build and start all 10 services docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d --build # Watch logs to verify startup docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ logs -f --tail=50
⏱ ~12 minutes on KVM 4

Both — Verify all containers are running

docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml ps # Expected output — all 10 services should show "Up": # NAME STATUS PORTS # dc-latest-postgres Up 5432/tcp # dc-latest-redis Up 6379/tcp # dc-latest-zookeeper Up 2181/tcp # dc-latest-kafka Up 29092/tcp # dc-latest-api Up 127.0.0.1:3001->3001/tcp # dc-latest-web Up 127.0.0.1:3000->3000/tcp # dc-latest-ai-service Up 127.0.0.1:8001->8000/tcp # dc-latest-intent-parser Up 8000/tcp # dc-latest-product-aggregator Up 8000/tcp # dc-latest-product-ranking Up 8000/tcp

Step 8. Set Up Nginx Reverse Proxy + SSL

Route all traffic through Nginx with automatic HTTPS

Install Nginx and Certbot

sudo apt install nginx certbot python3-certbot-nginx -y

Create Nginx site configuration

sudo nano /etc/nginx/sites-available/delegatecart
/etc/nginx/sites-available/delegatecart # DelegateCart — Nginx Reverse Proxy Configuration # Replace yourdomain.com with your actual domain server { listen 80; server_name yourdomain.com www.yourdomain.com; # Redirect all HTTP to HTTPS return 301 https://$server_name$request_uri; } server { listen 443 ssl http2; server_name yourdomain.com www.yourdomain.com; # SSL certificates (Certbot will fill these in) ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem; # Security headers add_header X-Frame-Options "SAMEORIGIN" always; add_header X-Content-Type-Options "nosniff" always; add_header Referrer-Policy "strict-origin-when-cross-origin" always; add_header X-XSS-Protection "1; mode=block" always; # ── Next.js Frontend (main site) ───────────────── location / { proxy_pass http://127.0.0.1:3000; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection 'upgrade'; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; } # ── NestJS API (/api/*) ────────────────────────── location /api/ { rewrite ^/api/(.*) /$1 break; proxy_pass http://127.0.0.1:3001; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; # Increase timeout for API operations proxy_read_timeout 60s; proxy_send_timeout 60s; } # ── AI Service (/ai/*) ────────────────────────── location /ai/ { rewrite ^/ai/(.*) /$1 break; proxy_pass http://127.0.0.1:8001; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } # ── Static file caching ───────────────────────── location /_next/static/ { proxy_pass http://127.0.0.1:3000; expires 365d; add_header Cache-Control "public, immutable"; } # ── Client-side max upload size ────────────────── client_max_body_size 10M; }

Enable the site and test Nginx config

# Enable the site sudo ln -s /etc/nginx/sites-available/delegatecart /etc/nginx/sites-enabled/ # Remove default site sudo rm /etc/nginx/sites-enabled/default # Test config for syntax errors sudo nginx -t # If test passes, reload sudo systemctl reload nginx

Get SSL certificate with Certbot

# First, temporarily comment out the HTTPS server block # and the HTTP->HTTPS redirect, then: sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com # Follow the prompts: # - Enter email for renewal reminders # - Agree to terms # - Choose redirect (option 2) # Verify auto-renewal works sudo certbot renew --dry-run
✓ Auto-renewal: Certbot installs a systemd timer that auto-renews certificates before they expire (every 60 days). Zero maintenance needed.

Step 11. Monitoring & Maintenance

Keep the stack healthy with minimal effort

Set up auto-restart on boot

Ensure Docker starts on boot and containers restart automatically:

# Docker starts on boot (usually default) sudo systemctl enable docker # All services have restart: unless-stopped in prod compose # So they auto-restart after reboot or crash

Create a simple monitoring script

nano /home/deploy/check-health.sh
check-health.sh #!/bin/bash # Simple health check for DelegateCart services echo "=== DelegateCart Health Check === $(date)" # Check web WEB=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000) echo "Web: $WEB" $( [ "$WEB" = "200" ] && echo "✓" || echo "✗ ALERT" ) # Check API API=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3001/health) echo "API: $API" $( [ "$API" = "200" ] && echo "✓" || echo "✗ ALERT" ) # Check AI service AI=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8001/health) echo "AI: $AI" $( [ "$AI" = "200" ] && echo "✓" || echo "✗ ALERT" ) # Memory usage echo "" echo "=== Memory ===" free -h | head -2 echo "" echo "=== Disk ===" df -h / | tail -1 echo "" echo "=== Container Status ===" docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}" | head -12
chmod +x /home/deploy/check-health.sh # Run manually anytime: ./check-health.sh # Or set up a cron to log every hour: crontab -e # Add: 0 * * * * /home/deploy/check-health.sh >> /home/deploy/health.log 2>&1

Docker cleanup (run monthly to reclaim disk)

# Remove unused images, containers, networks docker system prune -a --volumes --filter "until=720h" -f # Check disk usage by Docker docker system df

Update & redeploy workflow

# When you push new code and want to update the server: cd /home/deploy/delegatecart # Pull latest code git pull origin main # Rebuild and restart only changed services docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d --build web api # Or rebuild everything docker compose -f docker-compose.latest.yml -f docker-compose.prod.yml \ up -d --build

Step 12. Backup & Recovery

Hostinger includes free weekly backups, but here's how to add your own

Database backup script

nano /home/deploy/backup-db.sh
backup-db.sh #!/bin/bash # Backup PostgreSQL database — run daily via cron BACKUP_DIR="/home/deploy/backups" TIMESTAMP=$(date +%Y%m%d_%H%M%S) mkdir -p $BACKUP_DIR # Dump database docker exec dc-latest-postgres pg_dump -U admin ai_commerce | gzip > \ "$BACKUP_DIR/db_$TIMESTAMP.sql.gz" # Keep only last 7 days of backups find $BACKUP_DIR -name "db_*.sql.gz" -mtime +7 -delete echo "Backup completed: db_$TIMESTAMP.sql.gz ($(du -sh $BACKUP_DIR/db_$TIMESTAMP.sql.gz | cut -f1))"
chmod +x /home/deploy/backup-db.sh # Add to cron — daily at 2 AM crontab -e # Add: 0 2 * * * /home/deploy/backup-db.sh >> /home/deploy/backup.log 2>&1

Restore from backup

# Restore database from backup gunzip -c /home/deploy/backups/db_20260417_020000.sql.gz | \ docker exec -i dc-latest-postgres psql -U admin ai_commerce

Use Hostinger's built-in backups

Hostinger provides free weekly automatic backups of your entire VPS. To restore:

Go to hPanel → VPS → Backups → Restore. This restores the entire server state to the backup point.

💡 Belt and suspenders: Hostinger's weekly VPS backup + your daily DB backup script = you can never lose more than 24 hours of data.
